\# Anti-features (NEVER)



These are permanently out of scope because they contradict the product canon.



\## 1) Claims we never make

\- Any guaranteed metric improvement (“accuracy will increase”, “+X% uplift”)

\- Any causal/uplift statements presented as fact without proper experimentation



\## 2) Capabilities we never implement

\- Accuracy prediction / forecasting (direct “future metric” prediction)

\- Root-cause assertions (“the true reason the model fails is…”)

\- Automated ML optimization (architecture choice, hyperparameter tuning, loss selection, training loop changes)

\- Automatic decision-making (the system deciding or executing data actions by itself)



\## 3) Behavioral constraints (hard rules)

\- The workspace outputs hypotheses, not conclusions.

\- Every action must be explicitly linked to a hypothesis, risk, and cost.

\- Uncertainty must be made visible; hiding it is forbidden.

\- No “we know” language in system outputs.
